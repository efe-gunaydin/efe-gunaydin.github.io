Bu Ne?

Elasticsearch, "Apache Lucene" denen bir arama kütüphanesinin üzerine kurulmuş, milyonlarca dokümanı tarayıp milisaniyeler içinde sonuç döndürebilen bir arama motoru / NoSQL veritabanıdır. PostgreSQL'de WHERE description LIKE '%bisiklet%' sorgusu 10 milyon satırda kaplumbağa gibi yavaşlarken, Elastic aynı işi neredeyse anında yapar. Çünkü veriyi sıralı bir tablo gibi değil, inverted index denen "kelime → hangi dokümanlarda geçiyor" haritası şeklinde saklar.

Tipik kullanım: log aramak, site içi arama ("kullanıcı yazarken öneri çıkarmak"), ürün katalog filtreleme, analytics dashboard verisi (Kibana ile).

Mantığını Anla: Inverted Index

SQL nasıl tablo halinde tutuyorsa, Elastic kelimeleri tutar ve her kelimenin hangi dokümanlarda olduğunu işaret eder:

Bu yapı sayesinde "10 milyon satırı tara" yerine "sadece o kelimenin listesine bak" diye çalışır. Ölçek olarak fark uçurum gibi.

BE Developer Olarak Nasıl Kullanırsın?

Genellikle Java Spring Boot'ta spring-data-elasticsearch ya da resmi elasticsearch-java client'ı ile bağlanırsın. Yazma ve okuma şöyle görünür: 

// Java — bir ürünü Elastic'e yazmak
@Document(indexName = "products")
public class Product {
  @Id private String id;
  @Field(type = FieldType.Text) private String name;
  @Field(type = FieldType.Keyword) private String category;
  @Field(type = FieldType.Double) private Double price;
}

// Arama — "kırmızı bisiklet" gibi bir sorgu
NativeQuery query = NativeQuery.builder()
  .withQuery(q -> q.match(m -> m
      .field("name")
      .query("kırmızı bisiklet")
      .fuzziness("AUTO")))   // yazım hatasına dayanıklı
  .build();
SearchHits<Product> hits = template.search(query, Product.class);

Dikkat: fuzziness("AUTO") sayesinde kullanıcı "bisiklit" yazsa da bulur. Elastic'in gücü burada — SQL bunu rahat yapamaz.

Diğer Araçlarla İlişkisi

  • Logstash + Kibana: "ELK Stack" denen üçlüden ikisi. Logstash logları toplar, Elastic'e atar, Kibana'da görselleştirirsin.
  • Grafana: Elastic'i veri kaynağı olarak ekleyip dashboard çizebilir.
  • Backend servisin: Genelde "primary store" PostgreSQL/MySQL olur, Elastic ise "arama için secondary store" olarak çalışır. Veri iki yerde de tutulur, senkronizasyonu sen yönetirsin (event-driven veya periyodik job ile).
Stajyer notu
Elastic'i ana DB olarak kullanmaktan kaçın. ACID garantisi yok, "source of truth" olmaya uygun değil. PostgreSQL veriyi tutar, Elastic onu aranabilir hâle getirir — bu iş bölümünü kafanda netleştir.
