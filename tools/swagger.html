Bu Ne? Önce Terimleri Ayıralım.

OpenAPI bir spesifikasyon — yani "REST API'ni nasıl tarif edersin" standardı. YAML ya da JSON formatında bir dosyadır: endpoint listesi, her birinin metodu, parametreleri, request body şeması, response şeması, hata kodları. Swagger ise bu spec'i okuyup sana interaktif bir UI sunan araç ailesidir (Swagger UI, Swagger Editor, Swagger Codegen).

Önemi: Bir BE developer'ın frontend'çiye "tamam, şu endpoint şu parametreyi alır" diye Slack'te anlatması yerine, herkes Swagger UI'ı açar ve canlı dener. Üstelik bu döküman kodla beraber otomatik üretilir, yani güncel kalır.

Bir Endpoint Nasıl Görünür?

Kod → OpenAPI spec → Swagger UI dönüşümü

Spring Boot'a Eklemek

// build.gradle
implementation 'org.springdoc:springdoc-openapi-starter-webmvc-ui:2.3.0'

// Sonra /swagger-ui.html ve /v3/api-docs hazır.
// Annotation'lar ile zenginleştir:

@Tag(name = "Users", description = "kullanıcı işlemleri")
@RestController
@RequestMapping("/api/users")
public class UserController {

  @Operation(summary = "ID ile kullanıcı bul")
  @ApiResponses({
    @ApiResponse(responseCode = "200", description = "bulundu"),
    @ApiResponse(responseCode = "404", description = "bulunamadı")
  })
  @GetMapping("/{id}")
  public UserDto findById(
      @Parameter(description = "kullanıcının ID'si") @PathVariable Long id) {
    return userService.findById(id);
  }
}

Diğer Araçlarla İlişkisi

  • Postman: OpenAPI spec'ini Postman'e import edersin, tüm endpoint'ler hazır gelir.
  • Frontend takım: Spec'i alıp openapi-generator ile TypeScript client kodunu otomatik üretir. Elle endpoint yazmak yok.
  • API Gateway (Kong, Apigee): OpenAPI spec'ten gateway'i besleyebilirsin.
  • Kontrat testleri: Spec'i "kontrat" olarak kullanıp BE ve FE'nin uyumunu otomatik test ederler.
