Grafana

G
Kısaca
Farklı veri kaynaklarındaki metrikleri, logları ve trace'leri tek bir dashboard'da gösteren görselleştirme aracı.
↓ İndir ❯ Dokümantasyon ⌥ GitHub

Bu Ne?

Grafana kendi başına veri toplamaz — o sadece vitrin. Bir sürü data source (Prometheus, Elasticsearch, Loki, PostgreSQL, CloudWatch...) bağlarsın, üzerinde panel'ler (grafikler, sayaçlar, tablolar) kurarsın, bunları dashboard'a yerleştirirsin. Sistem 02:00'da yavaşladıysa sabah açıp "CPU mu, DB connection pool mu, dış API'nin latency'si mi?" diye bakıyorsan — bakacağın yer Grafana.

Bir BE servisin "sağlıklı mı?" sorusunun cevabı genelde 3 sinyal ile verilir: metrics (sayılar — CPU, request/sec, error rate), logs (olaylar — "kullanıcı 42 login oldu"), traces (bir isteğin servisler arası yolculuğu). Grafana üçünü de gösterir.

Observability Yığını — Grafana'nın Yeri

Metrik nasıl backend'den dashboard'a ulaşır

Önemli nokta: Grafana doğrudan servislere bağlanmaz. Arada Prometheus gibi bir "depo" olur. Servis metriği expose eder, Prometheus scrape eder, Grafana ondan sorgular.

Spring Boot Tarafında — Metrik Nasıl Yayarsın?

// build.gradle / pom.xml
implementation 'org.springframework.boot:spring-boot-starter-actuator'
implementation 'io.micrometer:micrometer-registry-prometheus'

// application.yml
management:
  endpoints.web.exposure.include: health,info,prometheus
  metrics.tags:
    application: order-service

// Custom counter — kaç sipariş oluştu?
@Component
public class OrderMetrics {
  private final Counter orderCreated;
  public OrderMetrics(MeterRegistry registry) {
    this.orderCreated = Counter.builder("orders.created")
      .description("oluşturulan sipariş sayısı")
      .register(registry);
  }
  public void incrementCreated() { orderCreated.increment(); }
}

Sonra Grafana'da PromQL: rate(orders_created_total[5m]) → son 5 dakikadaki sipariş/saniye hızı.

Diğer Araçlarla İlişkisi

  • Prometheus: Metrik için en sık eşlik eden ikilisi. "Prometheus + Grafana" deyimi vardır neredeyse.
  • Elasticsearch: Loglar Elastic'te tutuluyorsa Grafana data source olarak ekler, üzerine panel kurarsın.
  • Alertmanager / PagerDuty / Slack: Grafana'da "CPU %90'ı geçerse beni uyandır" kuralı kurarsın — sonuç bir bildirim olarak gider.
  • Jenkins / Argo CD: Deploy sonrası error rate fırladıysa Grafana'da görürsün → rollback kararı verirsin.
Stajyer notu
İlk haftada bir Grafana dashboard'u beğenip onu kopyalayıp düzenleyerek başla. Sıfırdan yazmaya çalışmak deli işi — community'de bedavası bol.
