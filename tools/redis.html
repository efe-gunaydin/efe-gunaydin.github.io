Redis

R
Kısaca
Veriyi diske değil RAM'de tutan, bu yüzden mikrosaniye seviyesinde okuma/yazma yapan key-value store.
↓ İndir ❯ Dokümantasyon ⌥ GitHub

Bu Ne?

Redis (REmote DIctionary Server) bir in-memory key-value veritabanıdır. PostgreSQL veriyi diske yazar — hızlı ama RAM kadar değil. Redis veriyi RAM'de tutar — disk'e göre ~100x daha hızlı. Aynı zamanda sadece "string" değil; list, set, sorted set, hash, stream gibi yapıları da destekler.

En yaygın kullanım: cache. Yani: yavaş bir sorgunun sonucunu Redis'e koy, bir sonraki istekte oradan oku → DB'yi yorma. Diğer roller: session storage, rate limiter, pub/sub mesajlaşma, distributed lock, leaderboard (sorted set burada parlar).

Cache Mantığı — Cache-Aside Pattern

Bir istek geldiğinde önce Redis'e bakılır, yoksa DB'ye gidilir

Spring Boot ile Bir Cache Örneği

// @Cacheable ile sihirli yol
@Service
public class UserService {

  @Cacheable(value = "users", key = "#id")
  public User findById(Long id) {
    // ilk çağrıda DB'den okur, sonra Redis'ten döner
    return userRepository.findById(id).orElseThrow();
  }

  @CacheEvict(value = "users", key = "#user.id")
  public User update(User user) {
    // güncellendiğinde cache'i temizle, yoksa eski veri okunur
    return userRepository.save(user);
  }
}

// Doğrudan template ile — özel ihtiyaçlar için
@Autowired StringRedisTemplate redis;

public void rateLimit(String userId) {
  String key = "rl:" + userId;
  Long count = redis.opsForValue().increment(key);
  if (count == 1) redis.expire(key, Duration.ofMinutes(1));
  if (count > 100) throw new TooManyRequestsException();
}

Diğer Araçlarla İlişkisi

  • PostgreSQL/MySQL: "Source of truth". Redis sadece hızlı kopya. Veri tutarsızlığı senin sorumluluğunda — yazınca cache'i invalidate et.
  • Mikroservisler: Çok kullanılan bir paylaşımlı veri için (örn. feature flag, kullanıcı session) servisler arası bir "buluşma noktası".
  • Pub/Sub & Streams: Hafif mesajlaşma için Kafka'ya alternatif olabilir (büyük ölçekte değil ama küçük olaylarda yeter).
  • Grafana/Prometheus: Redis'in metric exporter'ı var, hit ratio'yu izle. Hit ratio düşükse cache stratejin yanlış demektir.
Stajyer notu
"Cache invalidation is one of the two hard problems in CS" klasik şakası boşuna değil. Veri değişti ama cache hâlâ eskiyi gösteriyor → kullanıcı kafayı yer. TTL koy ve update sonrası evict et — bu iki kuralı unutma.
