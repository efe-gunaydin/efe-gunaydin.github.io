REST API

API (Application Programming Interface): "Bir programa nasıl konuşulur?" sorusunun cevabı. REST (Representational State Transfer) ise web üstünde API yapmanın en yaygın mimari stili. Bir zorunlu standart değil, bir dizi prensiptir — ama herkes neredeyse aynı şekilde uygular.

REST'in temel mantığı: Her şey bir kaynak (resource)'tır, kaynaklar URL'lerle temsil edilir, üzerlerinde HTTP metotlarıyla işlem yapılır.

REST'in özü: kaynak + HTTP metodu

HTTP Status Code'ları da REST'in kelime dağarcığı:

  • 2xx başarı — 200 OK, 201 Created, 204 No Content
  • 3xx yönlendirme — 301 Moved Permanently, 304 Not Modified
  • 4xx client hatası — 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found, 409 Conflict, 422 Unprocessable, 429 Too Many Requests
  • 5xx server hatası — 500 Internal Server Error, 502 Bad Gateway, 503 Service Unavailable, 504 Gateway Timeout

REST'in ana ilkeleri:

  • Stateless: Her istek bağımsız olmalı. Sunucu istemcinin "geçmişini" hatırlamaz; her istek kendi auth token'ı, parametresi vs. ile gelir.
  • Cacheable: Cevap "bunu cachele" diyebilir (Cache-Control header).
  • Uniform interface: Resource'lar, metotlar, status code'lar herkeste aynı görünür. Yeni bir API'ye baktığında ne yapacağını zaten anlıyorsundur.
  • Client-server ayrımı: Frontend ve backend birbirinden bağımsız evrilebilir.
Pratik
REST'i öğrendiysen "RESTful" olmayan API'leri de göreceksin. Örneğin POST /getOrder?id=42 (RPC tarzı). Standartlara uymayan API'lerle çalışmak zorunda kalırsın — kafanı koparma, gerçek dünya pürüzlüdür.
