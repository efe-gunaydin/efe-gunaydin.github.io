Şemayı 5 Akış Olarak Oku

Kutulara baktın, numaraları gördün. Şimdi her akışı takip et — hangi numara ne zaman devreye giriyor:

Akış 1 — Kod → Production (Deploy Zinciri)
01 Dev → 02 Figma → 03 Swagger → 04 DBeaver → 05 Postman → 06 Jenkins → 07 Registry → 08 Manifest → 09 Argo CD → 10 Cluster

Tasarımdan başlar: Figma'da ekran incelenir, Swagger'da API kontratı çıkarılır, DBeaver'da şema kararlaştırılır. Kod yazılırken Postman'de test edilir. git push Jenkins'i tetikler — build alınır, testler koşulur, Docker image registry'ye gönderilir. Jenkins manifest repo'daki image tag'ini günceller. Argo CD değişikliği yakalar, cluster'ı sync eder. Kötü kod production'a giremez — Jenkins fail olursa zincir kırılır.

Akış 2 — Kullanıcı İsteği (Sipariş Oluştur)
11 User → 12 Gateway (auth + rate limit) → 13 order-svc → 18 Redis (cart cache) → 17 Postgres (yeni kayıt) → 20 Kafka (event yay)

Kullanıcı butona basar. İstek Gateway'den geçer — JWT doğrulanır, rate limit kontrol edilir. Order servisi cart'ı Redis'ten okur (~1ms). Yeni order Postgres'e yazılır. OrderCreatedEvent Kafka'ya atılır. Kullanıcıya "Sipariş alındı ✓" döner. Toplam ~50ms.

Akış 3 — Async Event Zinciri (Ödeme + Bildirim)
20 Kafka → 15 payment-svc → 21 Stripe (ödeme al) → 20 Kafka (PaymentSucceeded) → 16 notification-svc → 22 SendGrid

Kullanıcı çoktan cevabı aldı — işler perde arkasında devam ediyor. Payment servisi Kafka'dan event'i tüketir, Stripe'a ödeme isteği atar. Başarılı olursa PaymentSucceeded event'i yayar. Notification servisi bunu tüketir, SendGrid ile "ödemeniz alındı" maili gönderir. Kimse kimseyi beklemez — async, decoupled.

Akış 4 — Arama (Full-text)
11 User → 12 Gateway → 13 order-svc → 19 Elasticsearch (inverted index sorgusu)

"ayakkabı" yazıp sipariş araması yapılınca Postgres değil, Elasticsearch sorgulanır. SQL'de LIKE '%ayakkabı%' milyonlarca satırda yavaşlar. Elastic inverted index ile milisaniyelerde döner. Sipariş oluşturulurken Elastic'e de yazılır — secondary store olarak.

Akış 5 — Observability (Alarm Geldi mi?)
13–16 Servisler → 24 Prometheus + metric 25 Loki + log 26 Tempo + trace → 27 Grafana → 28 On-call ↻ 01 Developer

Her servis sürekli 3 sinyal yayar: Spring Actuator → Prometheus (metric), stdout → Loki (log), OpenTelemetry → Tempo (trace). Grafana üçünü birleştirir, alert kuralı tetiklenince Slack/PagerDuty'ye atar. On-call müdahale eder — gerekirse developer'ı uyandırır. Döngü başa sarar (Akış 1'e).
